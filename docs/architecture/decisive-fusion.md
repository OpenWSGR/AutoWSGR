# 决战节点融合与采集

决战控制器拥有一个小关级 `DecisiveTrackingSession`，每场战斗借用该会话。
每次编队和修理后，根据当前舰队生成全节点 `CombatPlan.nodes`；索敌先更新定位，
阵型页和夜战页再读取对应节点的决策。不能定位且候选战术不同，使用复纵阵并开启夜战。
执行的战术不反过来作为定位证据。

## 完整流程与生命周期

1. 导航至章节总览。已有进度允许从 A 到终点任意位置恢复，模型保留全部候选。
   脚本重置后必须确认第一小关入口，才能建立 `A=1` 的强先验。
   总览页识别返回首个未通过标记的零基索引；控制器入口转换成领域使用的 1–3 小关号。
   全部通过标记与仍可进入的入口状态冲突时停止，不通过编号直接宣布通关。
2. 处理使用上次舰队、前进点选择、战备舰队购买等页面。
3. 稳定地图页通过两个不同解码帧检查舰标位置。按采样策略读取地图字母，
   定位和裁剪使用同一个 `CapturedFrame`，识别函数内部不等待、不重截。
4. 使用技能，必要时扫描已有舰队，选择舰船、编队、修理。
   未知恢复即使暂时判为 A，也必须扫描已有舰队；维修后再次检查停止请求。
5. 调用战斗引擎，传入本小关会话。每次索敌复用一次 native 与阵型 OCR 的结果，
   更新敌情因子。没有索敌画面或识别失败表示缺失证据，不等于空敌舰队。
6. 只有 `OPERATION_SUCCESS` 才提交 `encounter_complete`。唯一遭遇 ID 防止重复推进；
   推进作用于完整候选分布。停止、SL、船坞满和其他失败均不计步。
7. 等待真实战后页面。普通下一节点页面排除提前结束的候选；真实通关页面可覆盖
   滞后的进度估计。节点预测不能直接触发通关点击。
8. 确认结算控件，处理奖励，并验证回到章节入口。结束当前会话、汇总 native 异常反馈，
   下一小关重新建立 `A=1`。第三小关确认完成后，本轮才返回 `CHAPTER_CLEAR`。
9. 中止、暂离或异常结束会话。再次运行从实际页面恢复，不沿用上一次进程的预测节点。

`CombatEngine` 只负责本场战斗结束；外部注入会话时不发送整个小关的 `end`。
普通战和活动战不传外部会话，仍沿用原有生命周期。
普通战和活动战的同帧敌情采集异常时，仍调用既有敌情／阵型识别兜底，再执行战术规则；
兜底结果不作为失败原帧的融合证据。决战会话的缺失证据处理不改变这条既有路径。

购舰点击只表示尝试购买，不直接增加 `state.ships`；费用 OCR 错误或余额不足时，
卡片可能没有实际购入。发生购舰点击或使用副官技能后，准备阶段复用现有舰队扫描，
从实际编队及可用舰船刷新库存，再生成目标编队。购买和技能产生的刷新请求合并为
一次扫描，包括免费卡和技能卡；已有完整舰队且没有购买或使用技能时不会额外扫描。
分数识别得到的 `0` 会覆盖旧余额，不使用旧值代替零预算。

## 共享内核与场景策略

`FusionTracker` 保留唯一的前向计算、Viterbi 路径、历史平滑、历史修订和观测去重。
`MapDynamics` 保存普通／活动地图原有转移；`DecisiveDynamics` 提供顺序节点、
显式初始分布、已确认战斗推进和真实通关约束。

`EnemyFactor`、`GeometryFactor`、`NodeLabelFactor` 分别为全部合法候选产生对数因子。
敌情保留联合编成变体和同遭遇聚合；几何保留局部运动上下文与距离／射线混合。
跨事件历史由模型统一保存，历史和战后 `+1` 属于转移约束，不作为另两份独立投票。
决战地图不伪造入口、坐标或敌方阵型。

地图敌情采用中文简名，移除旧首位占位后规范为有序六槽。`AF` 对应机场，
`BG` 对应大巡，`BBG` 对应导战，`AP` 对应补给；空槽位置不挤压。
缺失敌情与已知空槽不同。84 个已有节点的反潜统计和战术选择由回归测试冻结。

## 主动采样与性能

`NodeSamplingPolicy` 集中定义滞回阈值：最高节点权重达到 0.95 时停止主动地图字母采样，
低于 0.80 时恢复；明显的终点／页面冲突也会恢复采样。确定 A 的起点直接跳过主动识别。
这些是模型权重阈值，尚未经过真实样本校准，不能解释成定位准确率。

停采只关闭主动地图字母识别。模型、完整候选和历史仍保留，后续已有敌情继续纠偏。
索敌缺失时，纠偏能力下降，但战斗成功仍能推进完整分布。
采集模式始终记录稳定地图字母，便于评估停采策略；它与生产模式的采样开关不同。

首轮保持 Python＋NumPy。验证使用冻结地图和原始观测逐事件比较权重、路径、歧义，
再统计排除截图、OCR、native、日志写盘的模型耗时。运行后台游戏时，应同时重跑旧版本
作为对照，避免把 CPU 负载变化误报为模型回退。

## 采集、反馈与回放

采集入口见 [tools/decisive/README.md](../../tools/decisive/README.md)。固定代码 worktree
与重构 worktree 分开，后台运行不能随源代码修改。用户配置文件保持原样，采集运行内
关闭 `useful_skill` 和 `useful_skill_strict`，启用 v4 回放。PID、有效配置、版本、停止入口、
进度及样本路径保存在输出目录。

样本保存稳定地图、节点裁剪、索敌、战果及通关前后画面，关联帧序号、单调采集时间、
遭遇 ID、native 版本、原始六槽、中文结果、阵型 OCR 和分项耗时。
`predicted_node` 与 `label_node` 分开；只有用户确认起点和已经验证的流程推进可产生标签。
未知恢复不能把预测节点写成人工真值。异常现场落盘后停止，修复后按实际剩余进度续采。

native 异常反馈仅帮助维护者复核识别，不自动调整参数，也不改变战斗决策。
独立参考定位重放排除敌情但保留场景、起点和推进规则。无法独立定位时只保留样本。
只有普通战第 3 槽适用战利品 AP 豁免；活动与决战不适用，其他槽也不适用。
正常补给匹配静默，整队补给模板过期资料豁免独立保留。

v4 回放冻结场景、初始条件、战斗模式、采样参数、中文地图与原始观测，逐事件核对在线结果。
旧版日志须使用对应旧提交回放。详细字段与反馈约束见
[node_fusion/README.md](../../autowsgr/combat/node_fusion/README.md)。

## 维护边界

完成事件以生产 `FusionTracker` 接受的 `encounter_complete` 为依据。采集器记录该事件的
原始时间与遭遇标识，离线转换按记录顺序重放，不通过阶段处理器返回时间推测新档案的推进。
旧档案缺少完成事件时，重建结果必须单独标明来源，不能用重建与自身回放一致证明在线行为一致。

| 数据或行为 | 权威所有者 | 消费者约束 |
| --- | --- | --- |
| 候选分布、合法转移、已接受的完成事件 | `FusionTracker` | 会话和回放读取结果，不再推断第二份完成事实 |
| 当前遭遇标识、主动采样 | `DecisiveTrackingSession` | 控制器和战斗引擎读取，不维护另一套遭遇计数 |
| 小关会话的创建与关闭 | `DecisiveController` | 单场战斗只借用，不能结束或重置整个小关 |
| 原始帧、原始识别结果和生产事件的归档 | `SampleArchive` | 记录来源事实，拒绝非空输出目录，不将预测改作标签 |
| 独立流程标签 | 采集器的已确认起点、完成事件与真实通关页 | 标签不参与敌情或字母证据，也不由模型预测反写 |

### 地图字母观察

`DecisiveMapController.observe_node(frame)` 以调用方提供的同一帧生成冻结的
`MapNodeObservation`，集中定位、裁剪、native 调用、首字符解析和分项耗时。
裁剪由原帧与边界派生，不复制整帧，也不另存可能失配的图像。图像沿用 `CapturedFrame`
的只读借用约定；冻结的是观察元数据。

`recognize_node(frame=None)` 保留省略帧时的一次截图及 `CHOOSE_FLEET` 返回约定，
`dll_recognize_map()` 保留原始字符串和异常传播。采集器直接归档共享观察，不再维护
定位和裁剪的另一套实现。页面门禁、采样与去重仍由各自调用方负责：生产识别异常视为
缺失证据，采集器归档 `map_error` 后停止。UI 只解析首字符 A-Z，小关成员校验由会话完成。

### 完成事实与决策投影

`FusionTracker.completed_encounter(id)` 通过接受事件索引返回首次确认的原始观察，
未完成或被拒绝的尝试返回 `None`。决战会话委托此查询，不另存完成集合；模型的原始
历史引用在追踪停用后仍保留，以供幂等查询和反馈使用。采集器按查询结果归档，不能通过
逆序扫描所有原始尝试来判断完成；它自己的归档去重集合只表示本消费者是否处理过事件。

会话 `estimate` 和 `current_node` 为只读属性，禁止直接赋值。`estimate` 返回最近一次
发布结果，包括被忽略事件的新事件号和诊断；`current_node` 从最近一次已发布的决策估计
投影，未确认时返回 `0`。二者有不同的发布时间，不能直接用模型最新估计替换：

- 普通、活动战的运动与非遭遇页面只更新最近结果，不重新发布决策节点；接受前进、迂回、
  撤退、结束动作后按既有条件清零，直到下一次遭遇确认。
- 决战的每次接受观察更新决策投影；忽略结果保留既有投影，推断异常优先清空投影。
- `state.node` 和引擎节点只记录业务执行快照，不反向约束模型。模型计算、采样阈值与
  v4 日志字段不因这些接口调整改变。

### 完整库存扫描与选船

`DecisiveShipListWalker` 共用于库存扫描和决战新旧换船算法。页面身份与“全部舰船／全部”
筛选必须正向确认；国家、舰种、状态或尺寸筛选都会改变综合筛选按钮，因此不能把筛选后的
空列表当作完整候选列表。系统离队卡须单独识别，不进入舰名集合；在队舰船由准备页六槽补入。

遍历器先确认顶部，每个视口等待两个不同解码帧稳定，再按完整卡位绑定规范舰名。向下
小步滚动须保留至少一整行有序重叠；保留重复舰名及顺序校验，全部验证后才转集合。
滑块到底还不够：尾部截断卡须继续滚动至完整覆盖。已确认顶部和底部的单屏库存直接完成，
不会为了极端溢出场景让正常单屏库存额外滚动。OCR 原位最多三次、视口稳定最多五秒、
回顶与向下遍历合计最多八十次滚动，预算耗尽、身份歧义、停止或覆盖丢失均抛扫描异常。
候选为空也必须正向确认：全量筛选、完整上下端点、无舰名蓝条及整个候选区域的已取证
深蓝空背景都须成立，再由两个不同解码帧确认稳定；存在离队卡时只排除已识别的控制卡区域。
从已占用槽和空槽进入分别验证，不能把 OCR 或定位失败当作空候选。
`scan()` 返回空集合只表示没有可选的备用舰船，不表示总库存为空；完整库存仍合并在队六槽。

`check_fleet()` 只有完成列表扫描、返回准备页并验证回到地图后，才返回原有三元组。
准备页未知占用槽复用既有单槽舰名 OCR，最多补识别两次；不注入预期编队或舰名池，
仍有未知槽或收到停止请求时不进入选船列表。
控制器一次性发布舰船、六槽编队和血量；失败保留旧业务快照与待刷新标志，并停止本轮。
`_inventory_refresh_required` 是唯一刷新标志：恢复、重置、小关转换、撤退、购舰点击与
技能尝试使其失效；完整扫描、返回和发布成功才清除。普通路径合并购买与技能刷新；
严格技能判断在库存失效时先扫描技能前库存，技能后再扫描。

决战选船每次重新进入列表都从实际顶部定位，使用当前稳定观察的点击坐标；两种换船算法
共用既有候选约束与点击逻辑。换船返回成功后仍独立核对实际六槽，再允许修理与开战。
普通战默认三轮找船与强化库存扫描保持原有业务流程，只复用底层卡片几何和滚动条识别。

第三批已完成实机验收：用玩家手动游玩后十五船、六空槽的真实现场确认首屏十四船、
滚动后新增 U-96、完整扫描及返回地图，以及新旧换船算法选中 U-96 后恢复空编队。
临时六舰在队后，九艘候选的单屏扫描零滚动，合并库存仍为十五艘；验收后恢复六空槽。
从溢出现场继承的非顶部位置仍需先回顶，这与单屏正常入口的零滚动路径分别验证。
空候选验收使用三舰在队、无备用舰船的真实现场；已占用槽与空槽的两个入口均返回零候选，
完整扫描与库存发布仍保留三舰、六槽和血量，验证往返地图，未改动编队或执行战斗。
这里的“空库”指可选列表为空，不要求总库存为空；筛选所得空列表不能替代该验收。

测试应区分算法、接口契约和实际页面验证。合成地图和像素输入用于确定性覆盖边界；
余额测试经过真实重试 helper，小关编号测试经过真实像素识别，采集顺序测试运行生产战后
处理器并转换其实际输出。控件模拟测试只证明流程协议，不能替代模拟器中的模板和页面验证。
