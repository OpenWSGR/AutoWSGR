# 自动强化分批实施 TODO

## 目标

按“素材优先、一次扫描、理论位置回放、逐目标滚动执行”的最小方案实现自动强化：

```text
主页面
→ 强化首页
→ 素材选择页
→ 全量扫描素材
→ 返回强化首页（不回主页面）
→ 目标选择页
→ 全量扫描目标
→ 生成规划
→ 按目标逐批选择素材并强化
→ 从内存素材快照删除已消耗 occurrence
→ 从列表顶部按新索引定位剩余素材
```

## 已确认前提

以下条件作为当前产品前提，不在本任务中重复证明：

- 素材和目标列表排序在一次执行期间稳定；
- 筛选条件、列数、卡片布局和分辨率保持不变；
- 强化期间不存在其他库存写入方；
- 每次定位前可以可靠回到列表顶部；
- 删除已消耗素材后，剩余素材按原有相对顺序前移；
- 当前排序下的理论位置可以由剩余有序 occurrence 列表的索引计算；
- 视觉完全等价的同名 occurrence 可按有序资源实例处理，不要求追踪跨 revision 的物理卡身份。

## 状态约定

- `TODO`：尚未开始；
- `IN PROGRESS`：当前批次正在开发；
- `DONE`：代码、专项测试和批次验收均完成；
- `BLOCKED`：依赖未满足或验收失败；
- 每批必须保持仓库可测试、可审查、可回滚，不允许依赖后续批次修复当前已知损坏。

## B5：纯强化规划器

**状态：DONE（离线测试通过，等待完整实机目标快照输入）**

### 输入

- 完整、有序的素材 observation；
- 完整、有序的目标 observation；
- 每个目标当前属性和上限；
- 每种素材的强化贡献和星级；
- 允许使用的素材身份或保护规则；
- 默认最高允许星级；
- 单次强化最大素材数量。

### 输出

按执行顺序生成批次：

```text
IntensifyPlanBatch
- target_ref
- material_refs
- expected contribution/gains
- material revision
- target revision
```

同时返回未分配素材的原始相对顺序，供后续理论位置计算。

### 规则

- 规划器是纯逻辑，不截图、不点击、不访问 API；
- 每个素材 occurrence 最多分配一次；
- 满属性目标不分配素材；
- 默认排除高星、受保护、贡献为零和语义不完整素材；
- 单批不超过游戏素材选择上限；
- 一个目标所需素材不超过上限时，一次性放入同一批；
- 超过单批上限时才为同一目标拆分多个批次；
- 优先减少无效属性贡献和明显溢出；
- 相同评分时按目标和素材原始 occurrence 顺序稳定决策；
- 相同输入必须产生相同输出；
- 不依赖或修改页面坐标。

### 验收测试

- 同名多 occurrence 不丢失、不重复分配；
- 高星和受保护素材不进入计划；
- 满属性目标不生成批次；
- 单批容量正确；
- 只有超过容量时才拆批；
- tie-break 稳定；
- 未分配素材保持原始相对顺序；
- 所有批次中的素材 ref 全局唯一。

## B6：按规划结果选择目标和整批素材

**状态：TODO**

### 范围

对一个 `IntensifyPlanBatch`：

```text
强化首页
→ 打开目标页
→ 回到目标列表顶部
→ 按当前目标有序 index 定位
→ 选择并返回强化首页
→ 打开素材页
→ 回到素材列表顶部
→ 按当前剩余素材列表索引定位本批全部素材
→ 一次性确认素材选择
→ 返回强化首页
→ 执行一次强化
```

### 定位原则

- 坐标只由当前有序列表索引临时派生；
- 有序 occurrence 列表是唯一状态源；
- 每次进入选择页后先恢复到列表顶部；
- 一次性选中本批全部素材，不逐素材执行强化；
- 单个目标若有多个批次，完成前一批并更新状态后再进入下一批。

### 最低点击前检查

- 当前处于预期选择页；
- 已返回顶部；
- 理论行列在有效范围内；
- 当前可见卡片身份与计划期望一致；
- 已选素材数与批次大小一致。

### 失败规则

任一步骤无法确认时停止整个执行序列；不得猜测、自动点击强化重试或继续下一个目标。

## B7：动态维护素材快照并滚动重规划

**状态：TODO**

### 权威状态

执行期间只维护：

```text
remaining_materials: ordered list[MaterialOccurrence]
current_targets: ordered list[TargetOccurrence]
```

不维护第二套可写坐标表。

### 每批成功后的更新

1. 确认本批强化已经完成；
2. 从 `remaining_materials` 删除本批使用的 occurrence；
3. 保持其余 occurrence 原始相对顺序；
4. 更新当前目标的属性；
5. 使用新列表 index 重新推导全部剩余素材理论位置；
6. 对剩余素材和目标重新运行纯规划器；
7. 执行新的首个批次。

### 理论位置

```text
row = index // column_count
column = index % column_count
```

实际滚动由目标 row 相对当前顶部可见行决定。任何位置均为派生值，不能反向修改有序列表。

### 成功判据

从内存快照删除素材前，至少确认：

- 强化操作流程已经结束；
- 素材选择状态已清空；
- 目标属性按预期方向变化。

结果不确定时：

- 不删除素材；
- 不更新目标；
- 不执行下一批；
- 整个序列停止并报告当前批次。

### 验收测试

- 删除首部、中部、尾部和多个 occurrence 后顺序正确；
- 同名 occurrence 删除数量正确；
- 理论 row/column 随 index 前移；
- 已消耗 ref 不会再次出现在规划中；
- 目标属性更新后会改变后续规划；
- 失败结果不会修改内存快照；
- 重规划保持确定性。
