# OCR 舰名可靠性与配置优化

## 状态

- OCR 和智能换船聚焦验证已通过。
- 本 feature 同时包含少量配置清理，不单独拆分配置 feature。

## 目标

OCR 结果必须结合 YAML 槽位目标，保证最终进入战斗的舰队逐槽一致。
无法可靠判断时返回 `None` 并重试或停止，不能按舰名数据库顺序猜测。

## OCR 改动

- 单字舰名只接受精确匹配。
- 编辑距离最近候选必须唯一；并列时返回 `None`。
- 短舰名收紧编辑距离，避免把单字或短片段强制映射为其他舰名。
- 长舰名只在片段证据唯一时接受。
- 准备页只使用当前槽位的 YAML 目标消歧，不跨槽补名。
- 保留 `/`、`-`、`·`，只修正确认过的局部误识别。
- 舰船等级严格限制为 `1-110`，并支持 `I/l -> 1`、`O -> 0`。
- 原图没有可靠舰名时才尝试 2 倍局部放大。

## 特殊规则

系统规则集中在 `autowsgr/vision/ocr_rules.py`。每条规则必须有实机证据，
并补充对应测试。

用户可在 YAML 中维护自己的舰名修正规则：

```yaml
ocr:
  ship_name_corrections:
    "OCR误识别文字": "SHIPNAMES标准舰名"
  ship_name_aliases:
    希尔德布兰德: AIII
    契卡洛夫: 85工程
    U-47·狼群: U-47
    巴尔的摩·英魂: 巴尔的摩
```

用户规则优先于系统规则。空规则、格式错误或目标不在 `SHIPNAMES` 中的
规则会被逐条跳过并记录警告，不阻止程序启动。
`ship_name_aliases` 用于登记用户自定义舰名，只接受“用户自定义名 -> 标准舰名”。
加载时会将自定义名加入标准舰名所属的 `No.xxx` 同船名称列表，同组名称不能
同时进入一支舰队。搜索保留用户自定义名，选船 OCR 接受同组任一名称，
已有同组舰船优先调位，最终编队核对也使用同一舰船身份。

## 配置优化

- 删除 `ocr.backend`：当前只会创建 EasyOCR，该字段不能切换引擎。
- 删除 `bathroom_feature_count`：后端和 GUI 均无消费者。
- 保留 `bathroom_count`：浴室修理流程仍在使用。
- 将 `operation_delay_min/max` 放入 YAML 的“脚本行为”，供用户设置全局
  UI 操作等待时间。
- 内置默认值先由 `config.py` 提供，YAML 用户值加载后覆盖默认值，再写入
  运行时 `OPERATION_DELAY_MIN/MAX`。
- 已核对配置查找顺序：显式路径、当前目录 `usersettings.yaml`、内置默认值。

## 已验证

- `蜂风` 不再因编辑距离并列误选为雪风。
- `鳟盹` 可由确定性规则修正为鳞鲀，不再误选胡德。
- `帅` 等单字误识别不再猜成其他单字舰名。
- `Il0/ll0/1l0` 可解析为 110，超出 `1-110` 的等级会被拒绝。
- YAML 目标不再跨槽补名。
- 用户别名可将四个显示名稳定映射到 `AIII`、`85工程`、`U-47` 和
  `巴尔的摩`，无需放宽全船池模糊匹配。
- 智能换船定向实机测试只搜索 `契卡洛夫`，已有岛风只调位，最终编队逐槽一致。
- 1 队槽位 0 和整队为空的拒绝逻辑已通过聚焦测试。

## 不在本轮处理

- 选船页面未退出或点击动画超时。
- 通过等级字体颜色判断 110。
- 统一删除舰名中的特殊符号。
- 决战 API、GUI 与 YAML 的配置来源冲突。
