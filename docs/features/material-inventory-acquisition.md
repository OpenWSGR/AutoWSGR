# 强化素材库存安全采集实现规范

## 状态

- `autowsgr/ui/material_first_intensify.py` 提供从主页面安全进入素材选择页的导航。
- `testing/fixtures/intensify-navigation/` 固定 Cetus 1920×1080 的主页面与素材选择页
  实机证据，专项测试同时验证唯一起点和素材页三组正向视觉证据。
- `autowsgr/ui/material_inventory_scanner.py` 已实现 Cetus 上的完整只读库存扫描。
- `autowsgr/ui/intensify_workflow.py` 已实现与识别方法解耦的强化规划、dry-run、一次性
  授权、操作状态机和事后校验契约；完整语义识别端口仍由当前或未来识别库实现。
- 目标、素材、收益和确认弹窗的语义观测由 `IntensifyRecognitionPort` 提供；当前 OCR
  或未来第三方识别库都可以实现该端口，不进入规划与操作核心。
- 当前实现不会猜测未校准的最终确认弹窗坐标。具体实机适配器必须显式注入已验证的
  `ConfirmationCoordinates` 和目标/素材 `SelectionOperator`。

## 目标

从已验证的主页面开始，安全进入素材选择页面，完整采集当前全部强化素材，并生成
一份只读、有序、可验证的素材库存快照。

采集流程只回答以下问题：

1. 当前素材列表中一共有多少张完整舰船卡片；
2. 每张卡片显示的舰名是什么；
3. 这些舰名按素材列表从上到下、每行从左到右的顺序如何排列；
4. 本次结果是否有足够证据声明为完整库存。

第一阶段暂不区分同名不同舰。同一个舰名出现多次时，每张完整卡片都作为一个独立
occurrence 计数，不能按舰名去重。

## 非目标

本功能不负责：

- 识别头像或根据立绘区分同名舰；
- 推断规范舰船 ID；
- 读取舰种、国籍、等级、星级、锁定状态或装备状态；
- 选择素材舰；
- 点击素材页面“确定”；
- 选择强化目标；
- 计算强化方案；
- 点击“强化”或任何不可逆确认；
- 消耗舰船或改变游戏内任何库存状态。

上述能力必须在素材库存采集稳定验收后，以独立功能和独立安全审查实现。

## 强化操作与规划契约

强化执行使用独立模块 `autowsgr/ui/intensify_workflow.py`。其核心状态为：

```text
HOME
→ TARGET_SELECTOR
→ HOME（目标已验证）
→ MATERIAL_SELECTOR
→ HOME（素材和收益预览已验证）
→ CONFIRMATION
→ HOME
```

规划器接收完整的 `MaterialInventoryObservation`、目标、最低收益和显式素材 allowlist。
每个同名素材必须具有独立 `SelectionRef`；规划器按最少素材数、最小超额收益和稳定的
occurrence 顺序选择组合，不按舰名去重。

识别端口只提供不可变语义 observation，不规定其内部使用 OCR、头像模型或其他库。
控制端口只消费 opaque `SelectionRef`，由具体选择器负责将引用解析为当前页面中的卡片。

HTTP 边界保持四个职责分离的端点：

- `POST /api/intensify/snapshot-sessions` 在一个设备租约内完成目标与素材只读扫描，且仅在
  两份完整快照均成功后创建短期 session；响应同时公开供 GUI 选择使用的不可变
  occurrence。目标仅包含 `ref`、`shipId`、`identity`、`occurrence` 和当前强化等级，
  素材仅包含 `ref`、`shipId`、`identity` 和全局 `index`；
- `POST /api/intensify/preview` 只校验旧版四字段手工策略，固定返回不可执行；
- `POST /api/intensify/snapshot-preview` 只消费服务端内存中的短期快照 session、素材
  identity allowlist、数量上限、一个 exact target occurrence ref 和 exact material
  occurrence refs，返回只包含所选目标的稳定候选预览；
- `POST /api/intensify` 继续 fail closed，不执行真实强化。

`snapshot-preview` 不获取设备租约、不读取设备，也不接受强化数据路径、舰船资料库路径、
validation proof 或执行授权。强化数据与舰船星级路径只能由进程环境配置，未知和过期的
session 对调用方统一表现为不可用。扫描 session 端点不接受请求体中的设备 serial、资源
路径或扫描结果；设备与识别资源只能来自已启动的进程上下文和受信任环境配置。GUI
只能使用 session 响应中的 opaque refs，不得用 HTTP 请求伪造快照或引用来补偿。响应
不得公开卡片矩形、截图坐标字段、视觉 hash、识别置信度、内部资源路径、设备信息或
授权 proof。

不可逆确认必须满足全部条件：

1. 当前库存指纹与计划一致；
2. 目标、素材 occurrence、顺序和收益在强化首页一致；
3. 确认弹窗中的目标、素材和收益再次一致；
4. 同一计划已完成一次打开确认弹窗后取消、清空素材且库存未变化的 dry-run；
5. 调用方使用该 dry-run 生成与计划和库存指纹绑定的一次性授权；
6. 确认点击在执行前标记为已使用，点击后验证失败也禁止自动重试；
7. 强化后目标属性按预期变化、素材槽清空，且新 revision 的完整库存必须等于旧库存按
   计划 occurrence 删除后的有序 identity 序列。旧 revision 的选择 ref 只用于执行前
   精确定位和授权，不能伪装成强化后可重新识别的跨 revision 物理卡身份；相邻同 identity
   occurrence 在删除后无法由视觉重扫区分，结果证据只能证明数量和有序序列变化。

`VerifiedIntensifyControl` 只内置已有截图证据的强化首页和素材“确定”坐标。最终确认与
取消坐标必须由具体游戏版本的可靠截图校准后注入，禁止依据经验猜测。

### Cetus 实机适配与贡献语义

`autowsgr/ui/live_intensify.py` 提供当前 Cetus 版本的具体页面判据、单素材目标/素材
网格操作适配、右侧滚动条安全定位和强化确认弹窗坐标；它不是完整语义识别端口。
网格引用必须保存扫描当时的实际卡片中心，不能只保存逻辑行列。确认弹窗已经通过一次取消 dry-run
和两次单击确认的实机流程校准：确认约 `(0.380, 0.568)`，取消约
`(0.620, 0.568)`。

素材选择页右侧显示的火力、鱼雷、装甲和对空数字是强化经验贡献，不等于目标最终面板
会直接增加相同数值。例如一艘大淀显示贡献为火力 11、装甲 14、对空 18，但实际面板
只会按照当前强化等级和经验进度产生有限的 `+N`。因此：

- `MaterialOccurrence.contribution` 和 `IntensifyGoal.minimum_gains` 用于规划素材经验；
- `IntensifyPlan.expected_gains` 必须在选中素材后，从强化首页实际显示的 `+N` 预览绑定；
- 事后属性验证使用首页 `+N`，不得直接使用素材页经验贡献。

## 历史手工流程回顾

### 1. 进入素材选择页面

已验证的最短流程为：

```text
主页面
→ 打开左侧栏
→ 点击改造入口
→ 点击强化子菜单
→ 确认当前为“强化”标签
→ 点击右侧素材槽
→ 素材选择页面
```

素材选择页面不要求预先选择目标舰。无目标状态下可以直接进入素材页面，也可以选择
素材。因此，未来库存采集不得为了进入素材页而临时选择一艘目标舰。

页面转移不能只依据点击次数或固定等待时间推定成功。每一步必须重新截图，并连续稳定
识别预期页面。起始页面未知或页面转移无法证明时，必须在下一次点击前安全中止。

关闭目标舰或素材选择页时必须点击页面左上角的游戏内返回箭头，并在点击后连续稳定
识别强化首页。不得使用 Android 系统 Back；Cetus 实机上系统 Back 会打开“是否退出
游戏”弹窗，而不是关闭选择页。扫描成功和异常清理使用同一返回契约，返回后状态无法
证明为强化首页时必须继续 fail closed，不能开始下一份库存扫描。

若库存扫描本身失败且选择页清理也失败，调用方必须保留原始扫描异常作为主错误，并把
清理失败作为附加诊断信息；不得用页面恢复异常覆盖舰船识别、连续性或完整性失败的真正
根因。扫描成功但清理失败时仍以清理失败中止，禁止继续下一阶段。

目标舰列表的前向遍历不能复用素材页滚动条拖动。Cetus 实机上目标页滑块即使请求
`1px` 移动也会跨过多行；因此目标页只使用 Scrcpy 小滚轮量子。每个量子后都必须读取
同一结果帧，并由目标扫描器用 `ship_id +` 稳定卡体视觉 hash 跟踪上一视口的末行：

- 锚点行丢失、重复匹配或 hash 超阈值时立即失败；
- 锚点未向顶部单调推进时立即失败；
- 只有锚点成为新视口首行且其后出现新完整卡片时，才计为一个逻辑滚动步；
- 裁切中间帧不消耗库存扫描的 `max_scrolls`，但也不得通过重试、反向滚动或放宽 merge
  补偿失败；
- 目标 occurrence 回放必须复用同一身份门控导航，不能按原始滚轮量子次数猜测位置。

### 2. 手工完整扫描素材列表

历史手工扫描从素材页顶部开始，采用以下方式记录列表：

1. 根据七个固定列位置检测青色卡片框；
2. 使用 native `locate()` 定位当前可见的舰名蓝条；
3. 只记录舰名蓝条完整可见、能够按固定七列裁切的卡片；
4. 使用右侧滚动条逐段向下移动；
5. 每次移动后重新检测当前视口卡片；
6. 使用相邻视口的重叠内容证明没有跨过整行；
7. 滚动条视觉到达底部后，继续确认真实内容底部；
8. 最后一行不足七张时，只记录实际存在的完整卡片。

该次手工扫描在强化前记录到 **59 张**素材。素材顶部包含一张 `72工程`，规范 ID
曾确认为 `474`。历史末页通过一次小幅补充移动显示最后不足一行的内容。

这里的 59 是当时库存事实，不是永久写死的产品常量。

### 3. 手工选择目标与素材

完整素材清单记录后，手工打开目标舰选择页面，定位并选择千岁：

```text
千岁规范 ID：570
等级：Lv.110
```

随后重新进入素材页面，选择一张 `72工程`，并在素材选择页面核对只有一张素材处于
选中状态。返回强化首页后，再次核对：

- 目标仍为千岁；
- 素材只有一张 `72工程`；
- 强化收益与预期一致；
- 最终确认前仍可取消。

正式执行前曾先完成一次 `confirm_irreversible=false` 的可撤销 dry-run：打开强化确认
弹窗后取消，清空已选素材，并确认库存没有变化。

### 4. 单次不可逆确认与结果复核

获得明确授权后，最终确认只点击一次，不进行自动重试。执行结果为：

```text
千岁装甲面板：16 → 17
千岁对空面板：28 → 31
72工程库存：1 → 0
素材总数：59 → 58
```

执行后通过目标属性变化、素材槽清空和素材库存减少三类证据确认成功。

这些历史结果只用于说明页面行为和验收方法。当前库存事实是 58 张且 `72工程` 为 0；
未来测试不得再次假设存在 `{474: 1}`，也不得以复现这次强化为测试目标。

## 当前导航基线

当前实现的状态机只包含：

```text
MAIN
→ SIDEBAR
→ INTENSIFY_HOME
→ MATERIAL_SELECTOR
→ 停止
```

对应状态：

- `MAIN`：主页面；
- `SIDEBAR`：左侧栏；
- `INTENSIFY_HOME`：强化首页的强化标签；
- `MATERIAL_SELECTOR`：素材选择页面。

素材页面判据必须至少包含：

- 左侧舰船网格区域存在足够的青色卡框证据；
- 右下角存在大型蓝色“确定”按钮；
- 右侧控制面板为深色；
- 连续多个稳定帧均满足判据。

目标舰选择页面没有同样的右下大型蓝色按钮，必须作为素材页识别的负例。不得只凭
“存在舰船网格”判断已经进入素材页面。

## 总体实现方案

允许以下两种采集实现。二者必须输出相同的中间模型、库存顺序和完整性证据。

### 方案 A：第三方长截图库

优先评估适用于 Android 模拟器的第三方长截图或滚动截图封装。允许该库内部执行受控
滚动、连续截图和拼接，对本功能提供一次长截图调用。

第三方库不要求调用 Android 原生 `ScrollCapture`。对于 Unity 游戏，第三方库很可能
仍然通过滚动和拼接生成长图，这是允许的。

第三方方案必须满足：

1. 能限制输入只发生在右侧滚动条安全区域；
2. 不点击或长按舰船卡片区域；
3. 能设置小步移动、稳定等待、最大移动次数和总超时；
4. 能保留原始视口或拼接诊断信息，便于证明没有漏行和重复行；
5. 拼接失败、重叠不足或无法确认列表末端时返回失败，不能输出伪完整长图；
6. 不引入任何头像模板匹配、特征点匹配或舰船身份识别；
7. 不得为了拼接素材内容而使用 SIFT、SURF、ORB 等局部特征算法。

获得长图后，应在长图上一次完成：

```text
固定列几何检测
→ 卡片/行切分
→ 提取所有完整卡片的舰名栏
→ 一次批量 OCR
→ 静态舰名表归一化
→ 生成有序 occurrence 列表
```

如果第三方库不能约束触摸区域，或者只能在列表内容区域长按拖动，则不得接入。

### 方案 B：原始视口扫描

第三方方案不可靠或不适用时，允许实现原始视口扫描。标准循环为：

```text
识别当前视口卡片
→ 分类每一行的可见状态
→ 处理当前舰名序列和连续性证据
→ 使用 ADB shell 在右侧滑块内部短距离向下拖动
→ 等待页面稳定
→ 验证仍为素材选择页面
→ 重复，直到证明到达真实列表底部
```

该方案不是自由滚动。每一步都必须由几何证据驱动，并受严格的移动范围、超时和失败
条件约束。

## 卡片几何检测

### 固定列

素材页每行最多七张卡片，横向列位置固定。实现应预先定义七个归一化列中心或窄列
扫描区域，不在整张截图上进行昂贵的通用目标检测。

每个固定列只通过简单像素规则查找卡片边界，例如：

- 青色边框的 HSV/RGB 范围；
- 列内水平或垂直投影；
- 连续像素段长度；
- 已知卡宽、卡高及容差；
- 同一行多列顶部位置聚类。

几何检测的输出只能是卡片框和行位置，不能尝试识别头像内容。

### 舰名蓝条模型

不再显式区分上半行、完整行和下半行。`autowsgr_native.recognition.locate()` 在标准化
后的 1280×720 BGR 图像上定位舰名蓝色背景的纵向行带；实现过滤高度异常的薄噪声行，
再结合固定七列确认每个实际存在的舰名格。

- 视口顶部仍完整显示舰名蓝条时，该行可以识别，但必须通过舰名序列重叠避免重复计数；
- 视口底部只显示头像、尚未显示舰名条时，native locator 不返回该行，当前视口不计数；
- 继续移动后，舰名条完整进入视口再识别；
- 一行可以少于七张，尤其是列表末行；
- 同一行中实际卡位必须从左到右连续，出现中间空洞时安全失败；
- native locator 只提供纵向行带，不能替代固定七列卡位检测。

## 舰名 OCR 规范

### 裁切区域

OCR 只能读取完整卡片底部的舰名栏，不读取头像、等级、舰种或其他文字区域。

已知卡片布局中，舰名栏位于卡片高度底部约：

```text
x: 0.02–0.98
y: 0.897–1.00
```

最终比例必须由真实无损截图夹具校准并锁定测试，不能在实机循环中尝试多个任意 ROI。

### 批量识别

一次视口或一张长图中的全部舰名栏必须通过一次批量 OCR 调用处理。禁止为同一批舰名
逐张初始化 OCR、重复多倍率识别或进行无限重试。

允许在 OCR 前进行统一、低成本的预处理，例如：

- 固定倍率缩放一次；
- 固定边距；
- 统一灰度或阈值处理。

预处理参数必须离线确定，运行时不能对每张卡执行参数搜索。

### 舰名归一化

OCR 文本只允许对静态舰名表归一化：

1. 精确匹配优先；
2. 已确认的字符清理规则；
3. 唯一候选子串；
4. 唯一最小编辑距离，且距离在严格阈值内；
5. 出现并列或歧义时拒绝。

第一阶段同名舰保持相同显示名，不使用头像消歧，也不强制生成舰船 ID。

## 原始视口滚动规范

### 允许的输入区域

只允许操作右侧滚动条轨道，1920×1080 实机上的已知安全横坐标约为：

```text
x = 1580 px
```

实现应使用归一化坐标，并通过分辨率换算到同一右侧安全区域。

每次只点击当前滑块下方一小段，随后重新检测滑块位置和页面内容。不得在一次动作中
假设滑块会移动固定距离。

### 严禁卡片区域手势

不得在左侧卡片网格区域：

- 长按；
- 拖动；
- 滑动；
- 点击后保持；
- 使用第三方库无法约束落点的滚动手势。

历史实机操作已经证明，卡片区域长按可能被游戏识别为点击并误选一艘素材。虽然当时
已取消选择并确认强化收益恢复为 0，但该行为必须作为永久回归风险处理。

### 移动后验证

每次移动后必须：

1. 等待动画结束并取得连续稳定帧；
2. 验证仍然是素材选择页面；
3. 验证滚动条或内容确实向下推进；
4. 验证当前舰名序列前缀能与累计库存后缀建立最长可信重叠；
5. 验证没有素材卡出现蓝色选中序号；
6. 验证没有进入确认弹窗或其他页面。

无法建立舰名序列连续性时，必须视为移动过度、OCR 失败、拼接证据不足或页面异常。

允许的处理只有：

- 在仍能证明当前状态安全时，回退滚动条并减小步长；
- 或立即安全失败。

不得把无法衔接的顶部行解释为“被跨过的新库存行”。

## 列表底部判定

滚动条视觉到底不等于内容已经完整显示。必须继续验证：

- 滑块已到达轨道底部；
- 连续安全移动后没有出现新舰名 occurrence；
- 末行允许不足七张；
- 再次安全推进时内容不再产生新完整卡片；
- 相邻视口或长图拼接证据没有断层。

历史库存的真实末页曾包含 `U-156` 和 `U-96` 两张完整卡片。它们是底部处理的真实
回归证据，但不是永久固定的末页内容。

## 库存结果模型

建议输出只读结果：

```python
@dataclass(frozen=True)
class MaterialOccurrence:
    index: int
    name: str
    row: int
    column: int


@dataclass(frozen=True)
class MaterialInventorySnapshot:
    occurrences: tuple[MaterialOccurrence, ...]
    total: int
    complete: bool
    acquisition_method: str
    viewport_count: int
    evidence_summary: str
```

约束：

- `index` 按从上到下、每行从左到右连续编号；
- 同名卡片各自占一个 occurrence；
- `total == len(occurrences)`；
- 只有所有连续性、页面状态、OCR 和底部条件均成立时，`complete` 才能为 `True`；
- 失败时应抛出明确异常或返回独立的失败类型，不能返回 `complete=False` 后由调用者
  猜测部分结果是否可用；
- 部分结果不得进入规划、缓存回放或强化执行。

当前账号在历史强化后已确认的验收样本为 58 张。针对当前固定实机快照的验收测试应
要求精确得到 58 个 occurrence；产品实现本身不能把 58 写死为所有用户的库存上限。

## 强制禁止项

以下内容禁止进入素材库存采集及其调用链，包括直接调用、间接回退、第三方封装和
“仅在 OCR 失败时”的备用路径。

### 禁止图像匹配和头像识别

- 禁止 SIFT；
- 禁止 SURF；
- 禁止 ORB 或其他局部特征点匹配；
- 禁止 `ShipPortraitLibrary`；
- 禁止 `ShipPortraitLibrary.identify()`；
- 禁止任何头像模板匹配；
- 禁止遍历舰船头像库；
- 禁止使用感知哈希识别舰船身份；
- 禁止从头像、立绘、背景、星级或舰种图标推断舰名；
- 禁止为了长图拼接而引入上述特征算法。

### 禁止高成本 OCR 策略

- 禁止逐卡重复初始化 EasyOCR/Torch；
- 禁止同一舰名栏多倍率轮询；
- 禁止无限 OCR 重试；
- 禁止针对每张卡搜索不同阈值或裁切参数；
- 禁止同时运行多个高 CPU OCR worker 争抢资源；
- 禁止 OCR 整张卡片或整张屏幕后从自由文本猜测身份；
- 禁止将歧义 OCR 强行归一化为某一舰名。

### 禁止危险 UI 操作

- 禁止点击任何素材卡片；
- 禁止在卡片区域滚动或长按；
- 禁止点击素材页“确定”；
- 禁止点击强化首页“强化”；
- 禁止点击不可逆确认；
- 禁止为了进入素材页临时选择目标舰；
- 禁止在页面状态未知时继续点击；
- 禁止在一次动作无反馈时盲目重复点击；
- 禁止使用错误模拟器 `127.0.0.1:16384`。

### 禁止伪完整结果

- 禁止将顶部或底部裁切行计入库存；
- 禁止依据滚动条到底直接宣称完成；
- 禁止在相邻视口无法衔接时继续累计；
- 禁止按舰名去重 occurrence；
- 禁止跳过无法识别的完整卡片；
- 禁止用历史固定列表填补当前 OCR 缺失；
- 禁止将部分结果交给强化规划或执行；
- 禁止因为当前验收值是 58 而截断多余卡片或补造缺少卡片。

## 错误处理

以下任一情况必须安全中止：

- 无法稳定识别主页面；
- 无法证明已进入素材选择页面；
- 页面被误识别为目标舰选择页面；
- 固定七列几何关系不成立；
- native 舰名蓝条无法稳定定位；
- 完整卡舰名 OCR 无法唯一归一化；
- 第三方长图存在无法证明的拼接断层；
- 当前舰名序列无法与累计库存衔接；
- 移动后滚动条或内容没有可靠推进；
- 出现素材选中序号；
- 出现确认弹窗；
- 滚动到底后仍存在无法补全的底部裁切行；
- 超过最大视口数、最大移动次数或总超时；
- 截图来源设备与指定 Cetus 不一致。

失败后不得点击素材确认、强化或不可逆确认，也不得通过额外盲扫尝试“凑齐”库存。

## 推荐实现分层

### 1. 导航层

继续由 `MaterialFirstIntensifyController` 负责：

- 验证主页面；
- 进入强化首页；
- 无目标直接进入素材页；
- 稳定验证素材页；
- 到达后停止。

### 2. 截图采集层

定义统一接口，使第三方长截图和原始视口扫描可以替换：

```python
class MaterialCaptureBackend(Protocol):
    def capture(self) -> MaterialCaptureResult: ...
```

采集层只负责截图、受控滚动、视口证据和长图生成，不负责舰名身份判断。

### 3. 几何解释层

负责：

- native 舰名蓝条定位和薄噪声过滤；
- 固定七列扫描；
- 每行实际卡位存在性检测；
- 舰名栏 ROI 生成。

该层必须是纯截图输入、纯数据输出，不得持有控制器或点击设备。

### 4. OCR 层

负责：

- 一次批量识别全部舰名栏；
- 静态舰名表归一化；
- 歧义拒绝。

### 5. 库存物化层

负责：

- 按视觉顺序创建 occurrence；
- 校验连续索引；
- 汇总完整性证据；
- 只在全部条件满足时输出完整快照。

## 测试要求

### 静态禁止项测试

必须增加静态测试，确保素材采集模块及其依赖不导入或调用：

```text
ShipPortraitLibrary
ship_portrait_matcher
identify(
SIFT
SURF
ORB
```

通用页面像素签名或非舰船身份用途的既有 matcher 不属于本禁令，但素材采集代码不得
通过它们识别舰船或拼接长图。

### 几何单元测试

至少覆盖：

- 七列完整两行；
- 顶部仍可见上一行舰名条；
- 底部只有头像而没有舰名条；
- 只有不足七张的末行；
- 空列不能生成虚假卡片；
- 动画中畸形框安全失败；
- 舰名栏 ROI 位于卡片底部而非等级区域。

### OCR 单元测试

至少覆盖：

- 一批多个舰名栏只调用一次批量 OCR；
- 重复舰名保留多个 occurrence；
- 唯一噪声归一化；
- 编辑距离并列拒绝；
- 完整卡任一舰名失败时整次采集失败；
- 顶部裁切行 OCR 结果不进入库存；
- 底部裁切行不调用 OCR。

### 滚动与拼接测试

第三方方案和原始方案都必须覆盖：

- 正常重叠；
- 移动过小产生大面积重复；
- 移动过大导致无法衔接；
- 滚动条视觉到底但底部仍有裁切行；
- 最后一行不足七张；
- 内容不再变化；
- 最大次数和超时；
- 全程没有卡片、确定或强化按钮点击。

### 实机只读验收

实机验收前必须先完成离线长图或视口序列回放。当前账号的固定验收样本应得到：

```text
total = 58
首屏顺序：
霞飞、埃塞克斯、埃塞克斯、埃塞克斯、企业、企业、企业
约克城、皇家方舟、皇家方舟、大黄蜂、大黄蜂、怨仇、怨仇
末页包含：U-156、U-96
```

实机采集完成后还必须确认：

- 没有素材卡出现选中序号；
- 没有点击素材页“确定”；
- 没有进入最终强化确认；
- 舰船库存没有变化；
- 远征暂停文件仍存在。

如果当前真实库存后来发生合法变化，应更新验收夹具和预期值，不得修改产品算法以迎合
旧的 58 张样本。

## 实施顺序

1. 保持当前进入素材页基线不变；
2. 定义统一采集结果和 native 舰名蓝条模型；
3. 调研并试验可约束右侧滚动条输入的第三方长截图库；
4. 使用现有无损视口序列离线验证第三方长图；
5. 同时保留可测试的原始视口采集后端作为兼容方案；
6. 实现 native 舰名蓝条定位、薄噪声过滤和固定列几何检测；
7. 在长图或完整视口集合上生成全部舰名栏 ROI；
8. 单次批量 OCR 并归一化；
9. 生成 occurrence 库存快照和完整性证据；
10. 通过 58 张固定样本离线验收；
11. 最后只执行一次 Cetus 实机只读验收。

任何阶段发现第三方库会触碰卡片区域、无法证明拼接连续性或隐含使用特征匹配时，应
停止接入并切换到原始几何视口方案，而不是放宽禁止项。
