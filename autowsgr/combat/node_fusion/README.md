# 节点融合追踪器

常规、活动地图及决战小关共用一个融合追踪器。旧节点追踪算法以及计划中的模式、融合参数配置项已删除，
不再并行运行旧算法。融合模型确认的当前节点用于白名单、阵型、迂回和战后前进决策。

## 模块边界

- `model.py`：标量推断、前向计算、Viterbi 路线和后向平滑，不访问设备或战斗引擎。
- `dynamics.py`：普通／活动地图与决战的初始化、合法转移和当前决策节点投影。
- `factors.py`：敌情、几何和节点字母证据；几何模块保留局部运动上下文。
- `state.py`：共享推断状态及历史层，不包含设备操作。
- `map.py`：地图校验、能力声明、路径枚举、快照指纹及 native 舰类集合。
- `geometry.py`：资料不足时的几何证据组合，以及已有路由的可达性约束。
- `position.py`：只检测本帧船位，不保存节点状态或复用旧船位。
- `enemy.py`：从同一索敌截图采集六槽、阵型和迂回按钮证据。
- `integration.py`：出征级 `TrackingSession`，适配观测、确认当前节点、保存诊断日志。
- `coordinates.py`：旧 YAML 坐标及入口读取，保留缺失信息，不包含追踪算法。
- `replay.py`：离线重放；`tools/node_fusion/replay.py` 只是命令入口。
- `calibration.py`：用排除敌情后的历史定位核对原始识别码，为用户反馈提供材料。

模拟器只提供通用 `CapturedFrame(image, sequence, captured_at)`，识别器保留实际匹配帧；
底层截图、点击、OCR 不知道融合状态或日志策略。日志写入失败只停用文件记录，推断继续。

## 控制与推断

隐藏状态保留节点或有向航段、页面阶段、同一次遭遇的敌情变体及迂回结果假设。
前向计算得到当前分布，Viterbi 给出最佳路线，后向平滑生成历史修订。已执行动作和原始
观测不可改写；`decision_node` 仅记录当时脚本节点，不作为证据，也不限制候选范围。

导航时的下一目的点不代表已经到达。只在遭遇页面证据确认后更新作战节点；异常或
无法消除歧义时节点为 `0`，沿用未知节点处理：索敌页撤退、阵型页 SL、战后回港。
资料不完整时仍使用同一融合模型的可用部分，详见下节。上述未知节点保护用于常规／活动
地图；决战使用小关级会话，在多次单场战斗之间保留候选，歧义决策采用复纵阵和开启夜战。
演习、战役不需要地图追踪。

决战通过 `FusionTracker(..., dynamics='decisive', initial=...)` 选择场景：确认重置或
确认上一小关通关后初始化为 `{'A': 1.0}`，未知进度恢复时 `initial=None` 保留全部候选。
经过确认的 `encounter_complete` 操作携带唯一 `encounter_id`，将整个分布推进一次；
重复战果不重复推进。历史与固定推进属于状态转移，不与观测分别投票。地图字母是软证据，
通关与下一节点页面约束合法候选，脚本的终点预测不能替代实际通关页面。

NULL、REWARD、LOSS 可以静默经过，几何证据按真实航段逐段评分，保留折线路径。
战斗节点构成的环路可重复经过；纯静默环路明确报告元数据异常，避免无限枚举。
距离与射线按加权混合组成一个几何因子，不是两次独立投票。帧间隔越大，方向权重越低。

六槽按位置对应；舰类集合与误识别类别数直接来自实际安装的 native `VesselType`。
同一次遭遇共享敌情变体，阵型与舰类联合匹配。未知槽位、NO、未知阵型与未检出迂回按钮
作为缺失证据。整帧异常项保留相关误识别的可能；重复读取只更新同一遭遇的聚合因子，
不按轮询次数连乘。每次真实迂回点击仅分配一次结果先验。

模型默认参数集中在 `FusionProfile`。舰类/阵型正确识别率初值 0.9、整帧异常权重 0.1
都尚待校准，输出权重不是实测正确率。普通地图按已验证的一秒航行下限约束：匹配帧在
实际迂回点击后不足 0.95 秒出现时排除下一遭遇；更晚出现不直接证明迂回成功。活动图
没有相同的实测时序保证，因此不使用该时间下限。

## 地图兼容与降级

常规地图只读取 Tracking JSON（当前完整资料包括 44 张常规图）；活动地图优先读取
Tracking JSON，文件不存在时回退读取同名旧 YAML（当前 20260930 活动 E/H 共 12 张图
有完整资料）。已有文件损坏、坐标非法或路由引用不存在时明确报错，不把错误资料
当作字段缺失。

| 可用资料 | 推断能力 |
| --- | --- |
| 起点、完整路由和节点类型 | 按合法路线推断遭遇历史，允许静默经过明确的非战斗点 |
| 缺部分敌情或迂回属性 | 保留路线和阶段推断，仅在缺资料的节点省略对应证据 |
| 缺节点类型或起点 | 使用距离、运动射线和已有敌情；完整路由仍约束可达范围，不按战斗次数推进 |
| 缺路由 | 使用几何及已有敌情，不采用拓扑硬约束，也不编造连接关系 |

未知字段使用 `None`，与明确的 `next: []`（终点）、`detour: false`（不可迂回）区分。
航段几何只要求当前航段两端坐标；较早起点缺坐标不会停用后续坐标完整的航段。
未知节点类型不会被当作 `NULL` 或战斗点；出现索敌、阵型等页面只确认新证据支持的位置，
不会自动前进一条边。只知道坐标时，没有本航段的新船位证据就不能确认下一个节点。

决战的 `MapData.tracking_map(chapter, stage)` 从中文 `enemy_spec.yaml` 构造顺序小关。
移除旧数组首位占位后规范成有序六槽，空槽保留 `None`；缺敌情、敌方阵型和坐标保持未知。
`AF→机场`、`BG→大巡`、`BBG→导战`，补给舰与机场独立处理。决战不伪造起点 `0`
或几何资料，由显式决战场景使用其确定推进规则。

降级时，路由约束以本航段的出发假设为基准，不把逐帧暂定位置变成已到达节点。
节点距离采用二维柯西核，射线仍按一维垂直误差评分；两者混合而非相乘。
没有路由时不输出虚构的连接；有路由但类型不全时，路线只表示一种可达解释，
不能据此确认中途经历了哪些遭遇。

旧 YAML 的裸数组坐标按原版 960×540 像素基准归一化；`position` 字段仍要求归一化值。
没有起点的地图不补造 `(0, 0)` 坐标。单入口 α/β 映射为 `0`；同图双入口保留各自坐标，
按格式明确的入口身份排除战斗候选。空地图无法定位。

每次出征降级时输出一次 WARNING，列出地图来源、缺失字段、保留能力及受限能力；
局部缺敌情不会停用其他节点的敌情匹配。启用回放时也将这些信息保存在标量日志中。

## 调试日志

完整回放 JSONL **默认关闭**，不创建目录或逐帧序列化副本。需要回放时在用户配置中开启：

```yaml
log:
  node_fusion_replay: true
```

启用后，每个会话在 `config.log.dir/node-fusion/<唯一编号>.jsonl.gz` 保存版本、模型参数、地图来源、
冻结的地图快照及指纹、能力与降级原因、原始观测、已执行动作和估计；未指定目录时
使用 `logs/node-fusion/`，不保存图片或录像。
普通 DEBUG 日志同步输出各路诊断结果，详细结构保存在 `diagnostics` 中：

| 字段 | 内容 |
| --- | --- |
| `history_prior` | 历史状态和合法地图转移产生的候选权重 |
| `distance` | 全图船位距离、似然及归一化候选，仅作独立观察 |
| `ray` | 全图射线距离、有效帧间隔、混合权重及不可用原因 |
| `enemy` | 六槽、阵型、联合敌情的各节点评分与候选 |
| `geometry` | 模型实际采用的航段评分，或降级后的节点几何评分 |
| `fusion` | 最终节点、航行目的点、最佳路线和历史修订 |

缺失证据明确标记不可用；不会把旧船位重复放入索敌观测。重复解码帧不重复计分，
同页相似观测按片段聚合。运动观测最多约每 100 毫秒发布一次，OCR 仅在索敌页执行。
日志以增量修订记录历史，避免每帧重复输出全部历史。

## 会话输出与完成查询

会话的 `estimate` 和 `current_node` 是只读输出，调用方须通过观察和操作更新状态，
不能直接赋值。`estimate` 保留最近发布结果的事件号、忽略原因和诊断；`current_node`
来自最近已发布的决策估计，因此普通、活动战运动期间及操作后清零时二者不一定相同。
模型的最新估计也不能替代会话的最近发布结果：被忽略观察会返回新的事件信息，但不更新
模型已接受估计。

`FusionTracker.completed_encounter(id)` 返回首次接受的原始完成观察，未接受则返回 `None`。
决战会话提供同名查询，并在活动追踪停用后保留原历史供查询。采集器的归档去重只记录
是否处理过该事件，不另行推断战斗是否完成；模型和 v4 日志格式不因此变化。

## 识别校验

会话结束时核对 native 敌方舰类识别：全程与地图签名一致则保持静默；出现不符时按节点
汇总 `[NodeFusion校验]` WARNING，携带模式、地图／小关、节点、槽位、期望中文舰类、
native 原始识别码及中文解释、native 版本，供用户向维护者反馈。每项还保留观测
`event_id` 与遭遇 `encounter_id`，便于关联采集记录。它不参与战斗控制，不自动修改
native 参数或 `FusionProfile`，也不因页面轮询重复告警。

参照节点由独立证据确定：排除本次出征的全部敌情读数，用地图、船位和页面历史重新
平滑定位，保留原场景和初始条件，要求权重至少 0.95 且与最佳历史路线一致。决战可使用
确定 A、经确认的推进和地图字母观测。该阈值是模型权重，不是校准后的准确率。
每次遭遇只取最早索敌帧，保留
首次识别失败；后续证据可以修正此前标签，校验不改写原始观测或已执行动作。只有节点
全部合法敌情变体中一致的舰类槽位才用于核对，不用待测结果挑选模板。

变体分歧槽、空槽、NO／未知原始码无法核对。无法独立定位时保留原始样本，不生成具有
确定节点标签的异常结论。原始码以当前安装的 native 枚举解释，例如机场通常输出
`Airfield`，资料里的旧 `AF` 只作为机场迁移别名。

反馈模块显式接收 `CombatPlan.mode`，不使用 native 识别布局参数 `fight` 推断战斗模式。

| 模式与模板 | native 原始读数 | 处理 |
| --- | --- | --- |
| 普通战第 3 槽（数组索引 2），期望非补给 | `AP` | 战利品补给豁免 |
| 普通战其它槽，期望非补给 | `AP` | 正常反馈不符 |
| 活动／决战任何槽，期望非补给 | `AP` | 正常反馈不符 |
| 任意模式，期望补给 | `AP` | 正常匹配，静默 |
| 全部合法变体整队都是补给 | 任意有效识别码 | 资料可能过期，独立整队模板豁免 |

最后一条是已有的资料可信度规则，与普通战第 3 槽战利品机制分开处理。

## 回放

```bash
python -m tools.node_fusion.replay logs/node-fusion/<编号>.jsonl.gz --output summary.json
python -m tools.node_fusion.replay logs/node-fusion/<编号>.jsonl.gz --labels labels.json --output summary.json
```

回放使用日志中完整的参数及冻结的中文地图，核对指纹、能力声明和模型版本，避免后来
更新的同名地图改变回放结果。当前日志格式为版本 4，模型版本为 `history-fusion-4`；
旧日志明确提示使用对应旧提交回放，不套用当前默认参数。v4 的 `start` 记录必须包含
`combat_mode`、`dynamics`、`initial`、`sampling`、完整 `metadata_snapshot` 和指纹。
普通／活动使用 `dynamics='map'`，决战使用 `'decisive'`；`initial=None` 与确定 A 分布
不能互换。采样阈值作为采集策略记录，不伪装成准确率或回放定位证据。每条观测保留
原始敌情、帧号、节点字母和遭遇编号，离线结果与在线估计逐项比较。
标量日志还保存 native 版本及实际舰类枚举映射。
回放直接读取明文或 gzip，不在原目录写入临时明文，也不修改输入文件。
坏的完整 JSON 行报错，崩溃遗留的末尾截断行可跳过并警告。
gzip 按 member 校验，末个 member 短写时恢复已解出的完整 JSON 记录并警告；
仅 trailer 截断时也保留完整末条记录，但尾记录缺少完整性校验，不能视为已验证数据。
损坏的 DEFLATE 数据、CRC 错误、中段截断和非 gzip 尾部垃圾仍报错，
不跳过后继续拼接记录；不完整的末尾 header 必须是合法 gzip header 的前缀。

`labels.json` 形如 `{"12": "C", "28": "E"}`，键为从 0 开始的观测 `event_id`，值来自
人工核实的实际节点。没有标签时不报告准确率；有标签时报告正确率、歧义、纠偏延迟。
不能把脚本自身节点输出当真值。

自动测试集中在 [`testing/combat/node_fusion/`](../../../testing/combat/node_fusion/)，
可运行 `pytest testing/combat/node_fusion/`。个人实测计划和本机日志不随包发布。
